# LinkedIn API capability matrix

Official documentation checked **2026-09-10**. This is a capability and access assessment, not evidence that a particular developer application has been approved. Product availability, scopes, versions, regional eligibility, and API terms can change. Some Microsoft Learn pages display an authorization banner even when their article text is public. Before deployment, confirm the app's actual grants in the LinkedIn Developer Portal and run account-specific integration checks.

The API adapters and conditional tool registrations below are implemented and covered by mocked tests. No live LinkedIn product approval or end-to-end account validation is implied; an unavailable permission fails closed. Unsupported capabilities are documented here and must not be registered as placeholder MCP tools.

## Identity and version decisions

LinkedIn OIDC discovery advertises pairwise subjects. The OIDC guide describes `sub` as the subject identifier; the Posts schema instead directs clients to retrieve a profile `id` and construct `urn:li:person:{id}`. The reviewed official pages do **not explicitly guarantee that `sub` and Person ID are interchangeable**. Store them separately. Resolve Person ID server-side through an actually authorized profile endpoint; otherwise leave actor-dependent calls unavailable until that application's mapping is verified. Never accept a user-supplied author ID as authorization. [OIDC discovery](https://www.linkedin.com/oauth/.well-known/openid-configuration), [Post schema](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/post-api-schema?view=li-lms-2026-08).

Use configurable `LinkedIn-Version: 202608` and `X-Restli-Protocol-Version: 2.0.0` for the selected REST endpoints. The official version page listed August 2026 as latest when checked. Review the version lifecycle before releasing or upgrading; do not invent `202609` solely from the calendar. OIDC `/v2/userinfo` is a different endpoint family. [Versioning](https://learn.microsoft.com/en-us/linkedin/marketing/versioning?view=li-lms-2026-08).

Single-post analytics use a Rest.li union query value such as `entity=(share:urn%3Ali%3Ashare%3A123)` or `entity=(ugcPost:urn%3Ali%3AugcPost%3A123)`, with `q=entity`, a supported `queryType`, and `aggregation=TOTAL`. Start with IMPRESSION, MEMBERS_REACHED, REACTION, COMMENT, and RESHARE. Do not substitute public engagement counts for impressions. API metrics can differ from LinkedIn's UI; preserve provenance and report unavailable values as unavailable. [Member Post Statistics](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/members/post-statistics?view=li-lms-2026-08).

## OAuth, refresh, and revocation

The documented confidential server flow uses `https://www.linkedin.com/oauth/v2/authorization` and `https://www.linkedin.com/oauth/v2/accessToken`, an exact registered redirect URI, a server-held client secret, and validated one-use state. The app must request only scopes enabled for its product and needed for its configured features. Scope changes require renewed member authorization. [Authorization Code Flow](https://learn.microsoft.com/en-us/linkedin/shared/authentication/authorization-code-flow).

LinkedIn documents PKCE for a separate native-client flow using `/oauth/native-pkce/authorization`. Do not assume that this native flow or its configuration automatically applies to the confidential server flow. ChatGPT-to-MCP authorization should independently require S256 PKCE; that protection is on the app's authorization server. [LinkedIn native PKCE](https://learn.microsoft.com/en-us/linkedin/shared/authentication/authorization-code-flow-native).

Programmatic refresh is available to approved Marketing Developer Platform partners. Store and use a refresh token only when LinkedIn actually returns one, honor both token expirations, and reconnect if refresh is absent or fails. Do not promise indefinite background access. [Programmatic refresh](https://learn.microsoft.com/en-us/linkedin/shared/authentication/programmatic-refresh-tokens).

No generally documented LinkedIn RFC 7009 revocation endpoint was established in this review, and OIDC discovery does not advertise one. Do not invent `/oauth/v2/revoke`. Disconnect must delete locally held provider tokens, invalidate the app's access/refresh grants, and give the user the provider-removal instructions. LinkedIn documents **Settings & Privacy → Data privacy → Permitted Services → Remove**. Report accurately whether local disconnection or provider removal has occurred. [OIDC discovery](https://www.linkedin.com/oauth/.well-known/openid-configuration), [Remove a permitted service](https://www.linkedin.com/help/linkedin/answer/a519947/third-party-applications-data-use?lang=en).

## Boundaries and deployment checks

LinkedIn has separate Member Data Portability programs for eligible members, including the EEA and Switzerland. These can cover data unavailable through baseline consumer scopes, including messages. This repository does not implement a portability adapter or infer its grants from standard OAuth. Future support requires its own eligibility, consent, data contract, and integration review; it is not a workaround for missing API access. [Member portability eligibility](https://www.linkedin.com/help/lms/answer/a552325), [Third-party data access](https://www.linkedin.com/help/linkedin/answer/a519947/third-party-applications-data-use?lang=en).

Before enabling a feature, record the app's product approval and exact granted scopes, perform a real integration check under the pinned version, and confirm actor ownership. Expose only configured capabilities. An OAuth scope is a provider permission; it does not replace ChatGPT's action approval or the server's per-user authorization checks.

LinkedIn rate limits vary by endpoint/application/member, and standard limits are not generally published. Respect 429 responses and inspect actual limits in the Developer Portal. The server's own rate limiter is additional protection, not a statement of LinkedIn's quota. [Rate limits](https://learn.microsoft.com/en-us/linkedin/shared/api-guide/concepts/rate-limits).

The minimum useful installation supports local drafting/routing plus connected OIDC identity/status. Posting becomes available with `w_member_social` and a trusted actor identity; comments/replies require the separate feed-write approval. Full historical audits remain useful with user-provided exports when restricted reads are unavailable. Scraping, cookies, reverse-engineered endpoints, browser automation, and invented scopes are excluded.
